# 编码器计数回绕：双读一致快照、剩余竞态与四个边界案例

> 证据等级：L1（源码审计）+ L2（Keil 0错误0警告构建，commit `4b5760d`）。
> 行号对应 Task5 提交后的源码：`BSP/MOTOR/motor.c`、`APP_TASK/app_tasks.c`、
> `BSP/MOTOR/motor.h`、`USER/main.c`。
> 无L3板端数据：回绕/换向边界需电机实机+示波器或长时间统计验证，
> 本文为L1级推演，mock无法模拟硬件中断时序。

## 1. 数据通路：16位硬件计数 + 32位软件扩展

```
编码器AB相（11线，TI12四倍频）
    │  TIM2_encode_init(0xFFFF, 0)（main.c:52）
    ▼
TIM2 CNT（16位硬件计数器，ARR=0xFFFF）──回绕──► TIM2_IRQHandler
    │（app_tasks.c:1384）
    │  TIM_GetCounter(TIM2)                       ├─ 清UIF标志
    │                                             ├─ g_tim2OverflowIrqCount++（诊断）
    │                                             └─ overflow++/--（按CR1.DIR方向）
    ▼
get_encoder_value()（motor.c:274）
    = (int)CNT + overflow * 65536   →  32位扩展计数值
    │
    ▼
SpeedCalcTask（app_tasks.c:1359，TIM4 50ms节拍触发）
    → get_speed()（motor.c:297）：Δcount×(1000/ms)×60 / 30减速比 / (11×4)线数
```

关键事实：

- `overflow`声明为`volatile int`（motor.h:18）——Cortex-M3上32位对齐
  读写原子，不会撕裂；
- ARR=0xFFFF（main.c:52）保证回绕模数恰为65536，与`×65536`拼接一致；
- CR1.DIR在编码器模式下只读，方向由硬件AB相位序决定。

## 2. 双读一致快照（seqlock读者模式）

```c
int get_encoder_value(void)               /* motor.c:274 */
{
    u16 cnt;
    int ovf_before, ovf_after;

    do {
        ovf_before = overflow;            /* ① 读软件扩展 */
        cnt = TIM_GetCounter(TIM2);       /* ② 读硬件计数器 */
        ovf_after = overflow;             /* ③ 再读软件扩展 */
    } while (ovf_before != ovf_after);    /* 不一致→期间发生过回绕中断→重读 */

    return (int)cnt + ovf_before * 65536;
}
```

思想：`overflow`是"纪元号"，`cnt`是纪元内偏移。①③之间若纪元变了，
说明②读到的`cnt`可能横跨新旧纪元，拼出的32位值会偏差±65536，
必须重读。这与Linux内核seqlock的读者逻辑同构（读者不阻塞写者，
只检测写者发生过，检测到就重试）。

它能捕获的窗口：回绕中断发生在①②之间或②③之间（`ovf_after≠ovf_before`
→重读）；以及双读窗口内连续两次回绕（`ovf`差2，同样≠→重读）。

## 3. 双读窗口的剩余竞态（核心声明）

**剩余竞态**：硬件计数器已经回绕（CNT已是新纪元低值），但TIM2中断
**挂起未执行**（UIF已置位，ISR被更高优先级中断或内核临界区延迟）。
此时读者执行：

```
① ovf_before = N（ISR未跑，还是旧值）
② cnt = 0x0005（硬件已回绕，读到新纪元低值）
③ ovf_after = N（ISR仍未跑）
→ ①==③，判定"一致"，返回 5 + N×65536
→ 真值是 5 + (N+1)×65536，本次采样偏差65536
```

窗口宽度≈一次中断响应延迟（Cortex-M3约12周期，外加临界区/高优先级
ISR阻塞时长）。电机场景下编码器回绕周期（65536脉冲/四倍频）远大于
该窗口，物理概率极低，但**非零**——这是"把竞态窗口从整个读取区间
缩小到三读+中断延迟窗口"的降险，不是消除。

后果量化：65536脉冲/50ms采样周期折算转速
`65536×20×60/30/44 ≈ 59578 RPM`量级尖刺。`get_speed`的10点中值滤波
（motor.c:317-330）可吸收**单次**尖刺；若连续命中（理论不可能，
需每个采样周期都恰好落在窗口内）则滤波失效。

**根治方案（本文档声明而未实施）**：重读条件追加UIF挂起检查——

```c
} while (ovf_before != ovf_after ||
         TIM_GetFlagStatus(TIM2, TIM_FLAG_Update));   /* UIF挂起→ISR将改overflow→重读 */
```

ISR执行清UIF后重读即可得到一致快照。未实施理由：当前剩余窗口在
本电机参数下物理上不可达（回绕周期vs中断延迟差4个数量级以上），
且该修复需要L3回归验证，遵循"无板不提交"的证据纪律。

## 4. 四个边界案例

### C1：上行回绕（0xFFFF→0x0000，DIR=0上行）

计数上行穿越ARR，硬件CNT回绕到0x0000，UIF置位，ISR读CR1.DIR=0
（上行）→`overflow++`（app_tasks.c:1399）。读者双读捕获。
数值例：overflow=N，真值65536×(N+1)+5；读者在ISR后进入循环：
ovf=N+1，cnt=5，两次ovf一致 → 返回65536(N+1)+5。✓

### C2：下行回绕（0x0000→0xFFFF，DIR=1下行）

计数下行穿越0，CNT回绕到0xFFFF，ISR读DIR=1 →`overflow--`
（app_tasks.c:1395）。负计数语义：overflow=N-1、cnt=0xFFFE →
返回`(int)0xFFFE + (N-1)×65536 = N×65536 - 2`，正确表达"净-2脉冲"。
✓ 双读同样捕获。

### C3：回绕与换向同拍（双读**无法**检测的持久偏差）

时间线：上行回绕发生（UIF置位）→ 电机恰在此刻换向下行（CR1.DIR
翻转为1）→ ISR被延迟，执行时读到DIR=1 → `overflow--`（错！本次
回绕是上行，应`++`）。结果overflow少计2（应为N+1，记为N-1），
此后**所有**读数持久偏差2×65536=131072。

为什么双读检测不到：错误在`overflow`**值本身**（ISR记账符号错），
不在读者读取时序——ovf_before==ovf_after完全一致，快照"一致地错"。

发生条件：换向必须落在回绕边界的±中断延迟窗口内（方向翻转与回绕
事件几乎同拍），概率远低于C4。检测手段需要"CNT变化方向与overflow
增量一致性"交叉校验，成本高于收益，未实施。

### C4：ISR挂起窗口（§3剩余竞态的实例化）

即§3时间线：硬件已回绕、UIF挂起、ISR未执行，读者三读恰好全部
落在该窗口内 → 单次采样偏差65536 → RPM尖刺 → 被中值滤波吸收单次。
这是四个案例中**唯一**可通过UIF检查根治的（见§3方案）。

## 5. 其他已知边界（完整性）

- `overflow`为`int`：±32767次回绕内安全；65536×32767≈2^31脉冲
  在电机寿命内物理不可达，无溢出风险；
- `get_speed`的`(1000/ms)`为整数除法（motor.c:314）：ms=50时
  1000/50=20整除，无损；若改采样周期为非2的幂整除值需先转float
（与TEMP归一化整数除法bug同类，已在注释中声明）；
- 首拍`old_value=0`起点：上电后第一次速度计算包含"开机以来累计
  计数"，首拍速度偏大——中值滤波+一阶滤波吸收，且首拍无控制意义。

## 6. 一句话总结

"16位硬件计数器用软件`overflow`扩到32位，读取用双读一致快照——
读`overflow`、读CNT、再读`overflow`，两次不一致说明期间发生过回绕
中断就重读，这是seqlock读者模式。它把竞态窗口缩到'硬件已回绕但
中断还没执行'的挂起窗口；剩余四个边界案例里最隐蔽的是回绕和换向
同拍——ISR按新方向记账旧回绕，错的是值不是时序，双读永远测不到，
我在文档里给出了方向交叉校验的根治思路。"
